# 퇴직금 계산기 · 퇴사 정리 · 챗봇 계산 API

사이트의 퇴직금은 세 곳에서 계산되지만 정본 엔진(`src/lib/calc/severance.ts`) 하나를 쓴다. 같은 합성 입력이면 세 곳이 같은 금액(고용노동부 퇴직금 계산기 값)을 내야 한다.

## Sub-features

- `sev-html` 퇴직금 계산기(`/tools/severance.html`) 산정서 한 줄 `× 30 × 재직일수 ÷ 365`.
- `sev-period` 산정기간 — 퇴직일 5.31 이면 3.1부터(2월에 같은 날이 없을 때).
- `sev-exit` 퇴사 정리(`/exit`) 의 퇴직금 추정.
- `sev-api` 챗봇 계산 API `POST /api/tools/calc {tool:'calc_severance'}`.
- `sev-link` 챗봇 답 끝 「계산기에서 직접 확인」 링크 — `?start&end(퇴직일)&w1~w3&run=1` 로 열면 자동 계산돼 챗봇 답과 같은 금액.

## How to get to it (user POV)

- 상단 메뉴 「퇴직금 계산」 → `/tools/severance.html`.
- `/exit` 퇴사 정리 화면의 「퇴직금 추정」.
- AI 노동법 대화에서 퇴직금을 물으면 같은 API 를 부른다(대화 경로는 이 절차에 없음 — API 를 직접 친다).

## Driving it with verify.mts

Preconditions:

- doctor OK.

- **계산기.** 입사 `2023-01-01`, 마지막 근무일 `2025-12-31`(261112~ 입력 칸은 마지막 근무일. 읽기 전용 칸 「퇴직일(산정사유발생일)」에 `2026-01-01`), 1구간 임금 `9000000`, 주 버튼 `button.btn-primary` 「계산하기」. `#resultArea` 의 결과 블록(`.result-block`)에 `97,826.09 × 30 × 1,096일 ÷ 365 = 8,812,389원`(`.result-formula`). 결과 첫 줄 `#resultStatus`(aria-live polite)에 「계산했습니다. 퇴직금은 8,812,389원 …」.
- **주 15시간.** 같은 입력에 「1주 소정근로시간(4주 평균)」 `14`. 금액 아래 「15시간 미만이라 퇴직금 지급 대상이 아닙니다」. `15` 면 그 줄이 없고 「14일째 되는 날까지」. 비우면 금액을 내지 않고 칸 위 `#calcStatus` 에 엔진 질문 「근로계약서나 근무표에 적힌 1주 근로시간이 몇 시간인가요? … 이 시간을 알기 전에는 금액을 내지 않습니다.」(261127 needs — 종전 261124 P2 #13 「비우면 따지지 않고 금액만 계산」을 뒤집었다). 계속근로 1년 미만이면 비워도 묻지 않는다. `14` 일 때 `#resultStatus` 도 「계산했습니다. 4주 평균 … 지급 대상이 아닙니다 … 같은 식으로 계산한 금액은 …」, 산정서(「산정서 보기·인쇄」) 위에 같은 문장과 금액 칸 「참고 계산액(지급 대상 아님)」(「실수령 퇴직금」 아님, 261126 G4 I10).
- **빼는 기간.** 입사 `2025-01-01`, 마지막 근무일 `2025-12-31`, 1구간 `6200000`, 접힘 「평균임금에서 빼는 기간(일)」 `30`. 「그 기간에 받은 임금」을 비우면 금액 없이 「빼는 기간에 받은 임금을 넣어 주세요 … 0을 넣습니다」(261126 G4 I8 — 전에는 0 으로 보아 분모만 줄었다). `0` 을 넣으면 `3,000,000원`, 산식 줄 「(92일 − 빼는 기간 30일)」(빼지 않으면 `2,021,739원`). 그 기간 임금 `6200000`(월급여 합계와 같음)이면 「남은 기간 임금이 0원」으로 멈춘다(I15). 「그 기간에 받은 임금」 칸에 들어갔다 나와도 `0` 은 `0` 으로 남는다(261127 G4 R14 — 전에는 포커스 때 0 을 지워 빈칸이 돼 멈췄다). 칸 아래 안내에 가족돌봄 등을 위한 근로시간 단축 기간(남녀고용평등법 제22조의4 제4항)도 들어 있다(R17). API·챗봇의 `excluded_wage: null` 은 빈칸과 같아 일수가 있으면 멈춘다(R11 — 전에는 0 으로 계산).
- **시간이 바뀐 적.** 1주 소정근로시간 칸 아래 체크 「재직 중 1주 소정근로시간이 15시간 이상과 미만 사이에서 바뀐 적이 있다」를 켜고 계산하기 → 금액 없이 「… 재직기간을 퇴직일부터 거슬러 4주 단위로 나눠 4주 평균 1주 소정근로시간이 15시간 미만인 4주는 계속근로기간에서 뺍니다(고용노동부 퇴직연금복지과-5254, 2019. 12. 9. 회신 취지)」(261127 G4 R16 — 「퇴직일부터 거슬러」 추가, 엔진 상수 `HOURS_CHANGED_MESSAGE` 하나를 웹·MCP·챗봇·/exit 와 MCP·챗봇 인자 설명이 같이 쓴다). 끄면 계산한다. 링크 `?hoursChanged=1` 이면 켜진 채 열린다(261126 재홍님 결정 D3 — 정밀 계산은 후속). MCP `hoursChanged: true`·챗봇 `hours_changed: true` 도 같은 글로 오류.
- **챗봇·API 지급 대상.** `/api/tools/calc` `calc_severance` 에 `weekly_hours` 를 넣으면 웹과 같은 `status`·`eligible`(1년 그리고 주 15시간), 없으면 `status: hours-unknown`·`eligible: false`·`severance_pay: null`(세금·실수령도 없음)·`needs: [{key: weekly_hours, question, why}]`, 근거 끝 「1주 소정근로시간을 몰라 금액을 내지 않았다」(261127 needs — 종전 261126 D2 「판정 보류 + 금액」을 뒤집었다). 응답에 `needs`·`assumptions` 가 늘 있다. MCP `calc_severance` 도 최상위에 `needs`·`assumptions`. 1년 여부는 `one_year`. `excluded_days`·`excluded_wage` 를 받는다(261126 D2 — 전에는 `eligible` = 1년만).
- **산정기간.** 새로 열어 입사 `2021-06-01`, 마지막 근무일 `2026-05-30`. 구간 글자 `3.1~3.31 4.1~4.30 5.1~5.30`.
- **/exit 와 같은 사람.** `?start=2023-03-01&last=2026-10-31&w1=3000000&w2=3000000&w3=3000000&run=1`. `× 30 × 1,341일 ÷ 365 = 10,782,311원`(/exit 운영 실측값과 같다).
- **퇴사 정리.** `/exit` 입력 칸에 마지막 근무일 `2025-12-31`, 입사일 `2023-01-01`, 월 급여 `3000000`, 주 시간 `40`. 「퇴직금 추정」에 `8,812,389원`, 기준일 줄 「법제처 현행 법령 원문 기준 · 확인 2026.10.21.」(exit-worker-data CHECKED).
- **퇴사 정리 — 시간이 바뀐 적.** 같은 입력에서 입력 칸 아래 체크 「재직 중 1주 소정근로시간이 15시간 이상과 미만 사이에서 바뀐 적이 있다」(`label.ex-check`)를 켜면 「확인용 추정」 첫 줄이 계산기와 같은 엔진 문장(「… 퇴직일부터 거슬러 4주 단위로 나눠 … 퇴직연금복지과-5254 … 회신 취지」)이 되고 「퇴직금 추정」은 `계산하지 않음`, 요약 줄에서 「4주 평균 주 15시간 이상·미만」이 빠진다. 미사용 연차수당 추정은 그대로다. 다음 할 일 「퇴직금 계산기 열기」 = `/tools/severance.html?weeklyHours=40&hoursChanged=1` — 누르면 계산기가 체크가 켜진 채 열려 같은 문장으로 멈춘다. 끄면 `8,812,389원` 으로 돌아온다(261126 재홍님 결정 E3). 입사일이 1년 미만(예 `2026-06-01`)이면 체크를 켜도 「퇴직일부터 14일 안에 받아야 합니다(근로기준법 제36조)」 안내가 남는다(261127 G4 R19). 주 시간 `0` 도 링크에 `weeklyHours=0` 으로 실린다(R20). 체크는 주소에 남지 않는다. /exit 의 계산기 링크는 `?…` 가 붙어도 정적 파일 링크(`<a>`)다 — 전에는 href 전체 끝이 `.html` 인지 봐서 `?weeklyHours=` 링크가 Next `<Link>` 로 갔다.
- **사업주 퇴사 정리(`/exit-employer`).** 퇴직금 추정이 없다(1년 여부 한 줄 + 계산기 링크 `/tools/severance.html`). 주 시간 입력이 없어 E3 체크를 넣지 않았다.
- **챗봇 링크.** `/tools/severance.html?start=2023-01-01&end=2026-01-01&w1=3000000&w2=3000000&w3=3000000&run=1` 을 연다. `end` 는 옛 뜻(퇴직일) 그대로라 마지막 근무일 칸에 `2025-12-31` 이 들어가고, 주 시간이 없어 금액 없이 시간을 묻는다(261127). `&weeklyHours=40` 을 붙이면 결과 영역에 `8,812,389원`(자동 계산). 챗봇이 1주 소정근로시간(`weekly_hours`)을 받았으면 링크에 `&weeklyHours=N` 이 붙어 「1주 소정근로시간(4주 평균)」 칸이 채워진다. /exit 「퇴직금 계산기로 자세히 계산」도 입력한 주 시간을 `?weeklyHours=N` 으로 싣는다(261126 G4 I16 — 전에는 늘 「따지지 않았습니다」).
- **API.** `hire_date 2023-01-01, last_work_date 2025-12-31, wages_3months [3000000×3]` → `result.severance_pay = 8812389` (PC 폭 실행 때 한 번).

## Gotchas

- 261124 화면 구조(디자인 평가 P1·P2). 첫 카드 「근무 기간과 월급여」에 `#startDate`·`#endDate`·`#wage1~4`(390 폭에서 세로 한 줄씩, 표 아님)만 있다. 나머지는 접힘(details)이다 — `#extraWages`(상여금·연차수당·중간정산·퇴직소득세·통상임금·적용임금), `#personalInfo`(사업장명·사업주·근로자성명·생년월일, 「산정서로 인쇄할 때 입력」). 접힌 칸을 채우려면 `summary` 를 먼저 누른다. 검증 오류가 접힌 칸이면 화면이 펴고 그 칸으로 포커스를 옮긴다.
- 오류 문장은 칸 바로 아래 `#<칸id>Error`(`.field-error`)이고 칸의 `aria-describedby` 에 들어간다. 버튼 위 `#calcStatus` 에도 같은 문장. 사라지는 토스트는 없다 — 저장·초기화·근로자 추가 결과는 `#actionStatus`(polite).
- 받는 방법 `#payout`(기본 현금 수령 — 기존 동작, 261125 결정. IRP 이전은 선택지, 근퇴법 §9②의 원칙): IRP 를 고르면 세금은 산출해 보여 주되 떼지 않아 「IRP 이전액」 = 퇴직금 전액(소득세법 §146②1). 현금 수령이면 뗀다. 단 소득세 1천원 미만이면 떼지 않고 지방소득세도 0(소득세법 §86 1호, 지방세법 §103의13①). 합성 기대값 = `tests/unit/severance-tax-withholding-p3.test.ts`.
- 결과 블록 순서: `.result-amount`(퇴직금 세전) → `.result-sub`(퇴직소득세·지방소득세(현금 수령 시) · 지급할 때 떼는 세금 · 「IRP 이전액」 또는 「세금을 뺀 실수령 추정」) → `.result-formula` → `.result-basis`(조문) → `.result-asof`(「YYYY년 퇴사 기준 · 퇴직소득세 세율표 확인일 2026. 10. 29.」 — 엔진 `BASIC_TAX_RATES[].checked`) → `.result-caption`(확인용 추정) → `.result-next`(14일 지급 기한 · `/tools/wage-delay-interest` · `/exit`). 서명란 산정서는 그 아래 `#statementBox`(「산정서 보기·인쇄」 접힘) 안 `.statement` — 인쇄(버튼·Ctrl+P 모두 `beforeprint`)할 때 저절로 편다.
- 링크로 열면(주소에 입력 칸 값이 하나라도 있으면 — `openedFromLink`) 저장본을 복원하지 않고 기본값에 주소 값만 넣는다. 저장본은 지우지 않아 주소 없이 다시 열면 돌아온다(261127 G4 R13 — 전에는 저장본 위에 주소 값만 덮어 앞 사람의 빼는 기간·임금·「시간이 바뀐 적」 체크를 이어받았다). `utm_source` 같은 다른 값만 있으면 저장본을 복원한다.
- 저장은 [저장](`onSave`)을 눌렀을 때만 한다(261124~, 자동 저장 폐지). 키 `severanceCalcData_v5` = `{ savedAt, format: 2, state }`(261127 R15 — `format` 이 없는 저장본은 「그 기간에 받은 임금」 기본값이 0 이던 때라 `'0'` 을 빈칸으로 읽는다). 표식 없는 옛 값(`_v4`·`_v3`)은 첫 로드 때 지우고 복원하지 않는다. 저장값이 있으면 폼 위 `#savedNotice`(「이 브라우저에 저장된 입력이 있습니다 · 지우기」). 인적사항 칸은 계산 결과를 지우지 않는다(`workerInputSignature` 에서 뺐다).
- 상단 탐색은 운영 GlassNav 를 정적 html 로 복제한 것이다(`nav.work-nav`, 데스크톱 5메뉴 + 다크 모드 단추 `.tool-theme`(aria-label 「다크 모드로 전환」) + 「서비스 문의」, 390 폭은 5칸 줄 + `.editorial-menu-toggle` → `#mobile-navigation`). GlassNav.tsx 메뉴를 바꾸면 이 파일도 고친다.

- severance.html 은 Next 화면이 아니라 정적 html 이다. 엔진은 `node scripts/build-severance-engine.mjs` 가 주입한다 — 엔진을 고치고 이걸 안 돌리면 동기화 시험이 실패한다. 블록은 둘이다: 퇴직금(`severance.ts`)과 퇴직소득세(`retirement-tax.ts`, 261029~).
- 퇴직소득세도 정본 엔진 하나다. 계산기는 마지막 근무일을 그대로 엔진에 넘긴다. 마지막 근무일 2022-12-31 이전이면 세액 칸에 「계산하지 않음」과 이유(법률 제19196호 부칙 제13조·제14조)가 나오고, 큰 글자는 어느 경우든 「퇴직금(세전)」이고(261124~), 그 아래 요약 줄과 산정서에 「퇴직소득세 반영 전 금액」이 나온다. `.result-asof` 는 「퇴직소득세는 계산하지 않았습니다」이고 세율표 확인일을 쓰지 않는다(「자동」을 끄고 직접 넣었을 때는 「직접 입력한 값입니다」). API 는 같은 경우 `tax` 없이 `legal_basis` 에 이유를 붙인다.
- 261112 부터 계산기·/exit·/tools/retirement-tax·API 가 모두 마지막 근무일을 받는다. 계산기는 하루를 더해 퇴직일(산정사유발생일)을 읽기 전용 칸에 보인다. 옛 저장값(v3·v4)은 261124 부터 옮기지 않고 지운다(위). URL 은 `last`/`lastWorkDate` = 마지막 근무일, 옛 `end`/`endDate` = 퇴직일(하루 뺀다). 챗봇 링크는 `severance-link.ts` 가 여전히 `end` = 마지막 근무일 + 1 을 넘긴다(261028 이전에는 안 더해 8,804,348원이 나왔다).
- 8,812,389원은 고용노동부 퇴직금 계산기(moel.go.kr/retirementpayCal.do)에 같은 입력을 넣어 받은 값이다(2026-10-28).

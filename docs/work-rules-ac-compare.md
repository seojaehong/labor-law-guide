- **A** = 브라우저 판정(표준취업규칙 2026 뼈대 + 개정 매핑 40건 + 제93조 각 호 낱말 점검). 본문은 서버로 가지 않는다
- **C** = `/취업규칙검토` 스킬(LLM 판정, 법제처 현행 조문 대조, 변경지시 JSON). 본문이 외부 모델로 간다
- **런칭 여부는 재홍님이 정한다.** 이 문서는 판단 자료다. 사이트·블로그에 일치율 숫자를 내지 않는다(NOW.md 「확률·적중률 숫자 출력 금지」)

## 개발 중 고친 A 결함 (2025년판에서 발견)

1. **명칭 변경이 다른 조문에 남은 경우** — 「배우자 출산휴가」가 제18조(휴직명령)에도 남아 있는데 A 는 제39조만 봤다 → 명칭 변경형 매핑(`everywhere`)은 문서 전체에서 옛 명칭을 찾는다
2. **제93조 제9호의2(사업장 환경 개선) 필수기재 누락** — 표준취업규칙에 대응 조문이 없어 A 가 볼 수 없었다 → 제93조 각 호 낱말 점검(`art93_check.json`)을 더했다. 첫 키워드 「신체적 조건」은 채용 조문에도 있어 오탐이라 뺐다
3. (보류 표본에서) **짝짓기 동점** — 「피해자의 보호」가 「임산부의 보호」에도 붙었다 → 제목 글자쌍 겹침으로 동점을 가른다

## A 가 C 보다 나았던 곳

- **육아기 근로시간 단축 거부 사유**(2026.9.18. 「대체인력 채용 불가」 삭제) — 기존 파이썬 판정 도구(`rules_impact.py`, B 와 같은 방식)는 두 표본 모두 「반영됨」으로 오판했다. A 는 짝지은 제46조 안에서만 보므로 「미반영」으로 잡았다. C 도 이 도구 결과를 믿지 않고 원문으로 뒤집었다(두 실행 모두 보고서에 「도구 오판」으로 적음)

## C 만 주는 것 (선택 기능으로 둘 이유)

- 회사 원문에 맞춘 **before/after 완성 문안과 anchor**(한글 파일 자동 개정 `/취업규칙개정` 으로 바로 이어짐). A 는 표준·매핑 문안을 줄 뿐 회사 문구에 맞추지 않는다
- **개선권고·표현 정비**(2023년판 22건) — 법 위반은 아니지만 정비할 곳
- 자리표시자(00:00·○○수당)·택일 안 잔존 같은 **양식 미완성**을 확인사항으로 분리
- 5단계 우선순위(🔴~⚪)와 시행 예정분 부칙 시행일 안내

## 판단에 쓸 만한 정리

- **기본 A 런칭에 걸리는 법령 관련 누락은 보류 표본에서 0건이었다.** 단 표본 2개, 둘 다 표준취업규칙 계열이라 회사별로 표현이 크게 다른 규칙에서는 짝짓기 실패가 늘 수 있다(그때는 「법령 확인」으로 떨어지고 B 방식으로 물러선다)
- C 는 A 가 못 하는 「회사 문구에 맞춘 개정 문안」과 「법 위반 아닌 정비」를 준다. 선택 기능(동의 + 대기 시간 안내)으로 두는 설계와 맞는다
- 남은 위험: 매핑 40건은 공인노무사 검수 전이다. 2023.1.~2025.9. 매핑 18건은 2인 반박을 거쳤지만 사람이 읽지는 않았다

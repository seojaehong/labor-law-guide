# 독립 검토 보완

SafeClaw 원본에서 상속한 결함을 이식본 입력·표시·내보내기 층에서 보완했다. 원본 저장소와 `annual-leave.ts`, `leave-ledger.ts`, `leave-promotion.ts`의 법정 산식·기간 계산은 수정하지 않았다.

1. 계산 실패는 화면·TSV/CSV·XLSX가 공통 판정을 사용한다. 미래 입사, 날짜 누락·잘못된 날짜, NaN/Infinity는 계산 불가이며 발생일수와 차이는 빈 숫자칸이다. 정상 일치·차이와 대장 원문은 구분한다.
2. 복사는 CSV 따옴표를 지우는 방식 대신 TSV 셀을 직접 직렬화한다. 사용자 문자열의 탭·개행·제어문자를 셀 내부 공백으로 정리하고 =,+,-,@ 시작은 텍스트 접두사로 보호한다. 계산된 숫자(-1 포함)는 숫자 그대로다. XLSX는 사용자 값을 문자열 셀로 유지하고 수식 셀로 생성하지 않는다.
3. ExcelJS가 해독한 날짜는 UTC 날짜 부분으로 정규화한다. 실제 날짜 서식 셀을 XLSX로 생성·재읽은 뒤 UTC·서울·LA 별도 프로세스에서 날짜가 같음을 검증한다. 같은 시간대의 local Date를 왕복하는 기존 잘못된 fixture도 교정했다.
4. 촉진 입력 검증층은 수령 전 회신, 발송 전 수령, 1차 절차 전 2차 통보를 차이로 표시한다. 같은 날 2차, 회신 기회 및 미통보·부분 회신 상태가 불확실한 경우 검토 필요로 남긴다. 마감 이전이라는 이유만으로 정상 일치나 적법 확정을 하지 않는다. 첫해 한 쌍의 날짜는 해당 묶음에만 대조한다.
5. 사업장이 없으면 명부 저장 안 됨과 선택 필요를 표시한다. 임의 사업장 생성이나 영구 저장을 하지 않는다. 저장 후 실제 읽어 온 명부를 대조해 성공 문구를 표시하며 저장 실패도 별도 표시한다.
6. ZIP 선언 크기뿐 아니라 항목별 스트림의 실제 해제량(2MiB/항목, 전체 5MiB)을 제한한다. 한도 내 실제 바이트만 STORE 형식으로 다시 묶어 ExcelJS에 전달한다. 입력 10MiB, 행·셀 수(5,000명, 행당 100셀, 전체 50,000셀) 제한도 적용한다. 합성·일반 STORE fixture로 항목/전체 한도 초과와 초과 행을 검사했으며 침해 파일이나 외부 직원 자료는 사용하지 않았다.
7. 첫 행이 날짜가 아니라는 이유로 헤더로 추정하지 않는다. 명시적인 이름·입사일 열 이름이 있을 때만 제외한다. 첫 직원 날짜가 잘못되고 둘째가 정상인 경우 두 행을 보존하고 첫 행을 오류로 표시한다. 직원 삭제를 허용하던 원본 테스트 기대값을 안전 동작으로 교체했다.

최종 결과는 PR16과 `docs/design-visuals/annual-leave-20261005/safety-browser.json`에 기록한다. 기존 298테스트와 새 회귀 34건을 합해 332테스트/38파일이며 실제 화면·복사·XLSX 다운로드와 LA 엑셀 입력을 브라우저에서 별도로 검사한다. 촉진 서면·도달·사용 보장, 근태 예외와 월말·윤일 법적 해석은 여전히 별도 검토다. Preview는 기존 보호 설정으로 빌드 결과만 확인하며 운영 병합·배포는 하지 않는다.

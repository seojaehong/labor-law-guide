# 연차 도구 이식 기록

원본: 사용자 소유 `seojaehong/safeguard-contest-mvp`, commit `bac5686dc73d1ad8df793e78bee4f9f8dbb5104d`, tree `798b27ccf1a6c1a7ec4d3183ad47df63aca56571`. 원본 로컬 체크아웃은 변경하지 않았다. 최신 원격의 검토 복사본에서 가져왔다.

`app/tools/leave`, `components/leave`, `lib/annual-leave.ts` 및 `lib/leave-*.ts`의 계산·대장 대조·퇴직 정산·사용촉진 일정·사용단위 환산을 재사용했다. 계산/정산 엑셀 파일 읽기, 열 매핑, 빈 서식, 결과 엑셀, 복사, 인쇄, 브라우저 사업장·명부 관리 기능도 유지했다. 원본 사용촉진에는 통지문·DOCX·ICS 생성이 없으며 이를 추가 기능으로 주장하지 않는다.

원본 저장소는 `private: true` 패키지이며 LICENSE 파일과 공개 라이선스 선언이 없다. 사용자의 동일 소유 저장소 간 이식 지시에 따라 재사용했다. 제3자에게 별도 사용 허락을 부여하는 기록이 아니다. `annual-leave.ts`는 HRMS Python 구현과 의도적으로 독립된 교차 검증 구현임을 명시한다. GPL HRMS 코드와 자산은 복사하지 않았다. ExcelJS는 기존 원본과 같은 4.4.0(MIT), 기존 패키지 버전 변경은 없다.

입력·파일·계산·내려받기는 브라우저 안에서 처리한다. 명부는 기본 sessionStorage이고 사용자가 기억하기를 켠 사업장만 localStorage에 남는다. 사업장 이름·역할·열 매핑은 localStorage에 저장된다. 삭제 UI를 유지한다. SafeClaw의 Vercel Analytics 및 클릭 이벤트 전송은 이식하지 않았다. 새 서버 API·회원 권한·발송·외부 캘린더 연동은 없다.

일의 무늬 원안 로고·공통 헤더를 사용한다. 기존 주요 메뉴 네 개는 유지하고 계산·점검 도구 목록과 추가 메뉴에서 연차 계산/촉진에 직접 진입한다. 선택적인 명부 관리는 접힌 영역에 두며 계산 전에 역할 선택을 강요하지 않는다. 원본 반응형 표와 인쇄 규칙을 유지하고 색상 토큰을 종이색·먹색·청록의 기존 테마로 연결했다.

공식 대조 기준: [근로기준법 제60조](https://www.law.go.kr/법령/근로기준법/제60조), [제61조](https://www.law.go.kr/법령/근로기준법/제61조), [고용노동부 개정 설명자료](https://moel.go.kr/policy/policydata/view.do?bbs_seq=20200301479), [1년 계약 근로자 해석 변경](https://www.moel.go.kr/news/enews/report/enewsView.do?news_seq=13052).

적용 전제: 상시 5인 이상·4주 평균 주 소정근로시간 15시간 이상. 상시 인원 산정 및 단시간 비례 산정 자체는 지원하지 않는다. 기본 계산은 개근/80% 이상을 전제로 한 입사일 발생 참조값이며 현재 잔여일수 또는 누계가 아니다. 회계연도 자동 부여, 80% 미만 월별 개근, 휴직·간주 출근, 회사 추가 부여분은 자동 계산하지 않는다. 월말·2월 29일 입사는 별도 법률 검토가 필요하다.

퇴사일은 마지막 재직일이다. 1년 종료 다음날 재직 여부를 구분한다. 사용촉진은 일반 연차와 첫해 두 묶음의 기간을 구분하며 9일/2일은 최대 개근 예시다. 첫해 묶음별 모든 통보 기록, 부분 회신, 서면 수령 및 실제 사용 보장, 적법성·촉진 완료·수당 면제는 판정하지 않는다. 날짜 일치가 법적 적합성을 뜻하지 않는 원본 제한을 유지했다.

원본 assertion 스크립트는 호스트 TS 경로·저장소 이름 및 process.exit→예외만 조정해 Vitest에서 실행한다. 독립 Python 기대값과 행정해석 사례, 원본 산식을 맞추려고 변경하지 않았다. 추가 경계 검증은 첫해 11일/발생 누계26일/현재분15일, 근속3년16일, 80%와79.99%, 일반 촉구/통보 경계 및 첫해 별도 촉구 창을 다룬다.

운영 병합·배포는 새 기능 검토 전까지 보류한다. 실제 직원 정보, 유료 AI, 서버 업로드, 이메일/문자 발송, 외부 캘린더 등록은 검증에 사용하지 않는다.

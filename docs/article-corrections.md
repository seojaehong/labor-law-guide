# 기사 정정과 캐시 갱신

관리자 `PATCH /api/admin/articles` 저장 성공 시 해당 글의 상세(본문·메타데이터·JSON-LD), OG 이미지,
글/카테고리 목록 캐시를 무효화한다. 목록은 본문에서 요약을 생성하므로 페이지·필터별 결과에 공통 태그를 쓴다.
기존 태그 없는 캐시와 섞이지 않도록 목록 캐시 키는 v2로 전환했다.

직접 SQL로 정정한 경우 DB를 다시 저장하지 말고, 기존 `x-admin-token` 인증으로
`POST /api/admin/articles/{slug}/revalidate`를 호출한다. 본문이나 임의 경로는 받지 않는다.
DB에 있는 slug만 허용하며 이 경로는 DB에 쓰지 않는다. 새 키 설정은 필요 없다.
`revalidated: true`는 무효화 요청 성공이며, 운영 표시 확인을 대체하지 않는다.

호출 후 공개 `/blog/{slug}`를 새로 요청하여 정정 문장과 이전 문장의 부재를 확인한다.
상세 HTML에는 메타데이터도 함께 생성된다. 목록 데이터 태그는 즉시 만료시키며,
상세/OG 경로는 다음 방문에 재생성한다. 이미 열어 둔 화면은 새로고침해야 한다.

2026-10-20 조사: `daily-20261020-01`의 `blog_articles.content`에는
8월 천안 사고가 상반기 32명에 포함되지 않는다는 정정이 이미 저장되어 있었다.
상세 페이지는 이 content를 직접 렌더링한다. DB 본문·updated_at은 변경하지 않았다.

## Cost safety

BudgetStore uses a private persistent ledger with an exclusive process-shared filesystem lock and atomic file replacement. Integer micro-USD reservations precede every provider start. Duplicate request IDs, monthly exposure over cap, unreadable/corrupt storage and stale locks deny new calls. Missing storage after initialization also denies rather than resetting. Pending and unknown previous-month reservations carry into the new month's exposure. The ledger stores only opaque request IDs, month, model, call count, token counts when authoritative, cost/reservation, latency and success/abstention/unknown state; no prompts, responses or attached source material.

Timeouts and provider errors keep the maximum reservation. There is no automatic fallback or retry. An AbortSignal is not taken as proof that an SDK stopped billing; late completion after timeout cannot release reservation. Confirmed bounded usage may settle a generating request. PR27 does not expose usage/status, so Jev keeps the full maximum even on a returned result. This is conservative accounting, not measured actual spend. Fixture prices and monthly cap are test units, not a pricing recommendation.

The filesystem store only coordinates processes sharing the same directory. It is not a verified distributed or serverless budget database. Production activation remains blocked; a durable shared atomic implementation and approval are required before a multi-replica rollout. Unknown Jev usage reconciliation is also pending.

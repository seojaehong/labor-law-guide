# 취업규칙 기간 점검 — 표준취업규칙 2026 뼈대 + 개정 기간 지정

- 작성 2026-10-05 · 재홍님 승인 설계(대화) · 브랜치 `feat/work-rules-period`(PR #11 `feat/law-revisions` 위)
- 화면 `/laws` 안 「내 취업규칙 점검」을 확장한다. 별도 화면을 만들지 않는다

## 1. 목적

「2025.1. 에 만든 취업규칙을 오늘 개정해야 한다」는 실무자에게, **그 사이(또는 시행 예정분까지) 바뀐 법령 중 취업규칙에 걸리는 것**을 조문 단위로 모아 바꿀 문안과 신구대조표를 준다.
같은 구조로 **표준취업규칙 2026 조문 전체를 기준으로 한 1차 점검**(빠진 필수 조문·확인할 관련 법령)을 한다.
캘린더(.ics) 저장은 이 기능의 범위가 아니다(추후 검토).

## 3. 데이터

### 3.1 `scripts/laws/standard_rules.json` (원천) → `public/data/laws/standard.json` (사이트)
표준취업규칙 2026(고용노동부 2026.2. 배포, `employment-rules-reviewer/references/표준취업규칙-2026.md`) 일반 근로자용 조문.

```
{ "no": "제30조", "title": "연차유급휴가", "chapter": "제7장 휴일·휴가",
  "kind": "필수" | "선택", "text": "<표준 문안>", "note": "<착안사항 원문>",
  "laws": [{ "lawId": "001872", "law": "근로기준법", "article": "제60조" }],
  "keywords": ["연차", "유급휴가"], "status": "auto" | "checked" }
```
- `laws` 는 착안사항의 법령 인용(「~ 참조」·「법 제N조」)과 조문 본문의 법령 인용에서 자동으로 뽑는다(`extract_standard_rules.py`). 약칭(남녀고용평등법·기간제법 등)은 표로 정식 법령명·lawId 에 잇는다
- 인용이 없는 조문의 `laws` 는 비어 있어도 된다. 이 조문은 「표준 문안 대조」만 한다
- `status` = auto(자동 추출) / checked(2인 반박 검수 통과). 화면은 auto 도 쓰되 책임 표시에 「자동 추출」로 밝힌다
- `keywords` 는 제목 낱말 + 사람이 더한 동의어. 사용자 조문 짝짓기에 쓴다

### 3.2 개정 이벤트 ↔ 표준 조문
이벤트의 변경 조문(lawId+조문)이 표준 조문 `laws` 에 있으면 그 표준 조문에 걸린다. 하위법령 개정은 상위 법률 lawId 로도 걸린다(`group`).
기존 매핑(`work_rules_map.json`)은 표준 조문 번호(`std`)를 더해 그 조문의 「바꿀 문안」이 된다.

### 3.3 수집 범위 확장
`fetch_law_revisions.py --since 20230101` 로 다시 수집한다. 서버1 크론(`daily_update.sh`)은 커밋된 `since` 를 따라가므로 손댈 것이 없다.
2023.1.~2025.9. 시행 개정 중 취업규칙에 걸리는 것은 `work_rules_map.json` 에 매핑을 더한다(원문 대조 + 2인 반박, 기존 방식).

## 4. A — 브라우저 판정

1. **입력** — 붙여넣기 또는 파일(hwpx: `Contents/section*.xml` 의 `hp:t`, docx: `word/document.xml` 의 `w:t`, 문단 단위). jszip 사용
2. **짝짓기** — 사용자 조문(「제N조(제목)」 덩어리)을 표준 조문에 잇는다. 점수 = 제목 일치 > 제목 키워드 > 본문 키워드. 한 사용자 조문이 여러 표준 조문에 걸릴 수 있다(예: 「휴일·휴가」 통합 조문)
3. **기간 판정** — 기간 [최종 개정일, 기준일] 안에 시행되는 이벤트 중 표준 조문에 걸리는 것. 매핑이 있으면 `judge`(ok·stale 문구)로 반영됨/미반영/누락, 매핑이 없으면 「법령 확인 필요」
4. **표준 점검** — 짝을 못 찾은 [필수] 표준 조문 = 「필수 조문 누락」. [선택] 은 목록만
5. **결과물**
   - 조문별 카드: 내 조문 원문 / 바꿀 문안 / 근거(법령·조문·시행일·출처 링크)
   - 바꿀 문안: 매핑 `clause` 가 있으면 그것, 없고 시행일이 2026.2. 이전이면 표준 문안, 둘 다 없으면 「바뀐 조문 원문만」
   - 내려받기: 신구대조표 **docx**(한글에서 열림) · **엑셀** · 표 복사(한글·엑셀에 표로 붙음, 기존 `copyRich`). hwpx 생성은 이번 범위가 아니다
   - 취업규칙 없이 기간만 고르면 그 기간 문안 묶음과 신구대조표(내 조문 칸 비움)를 준다
6. 책임 표시: 「1차 자동 점검입니다. 표준취업규칙 2026(고용노동부)과 법제처 원문을 기준으로 하며 공인노무사 검수 전입니다. 판정은 이 브라우저 안에서만 했고 본문은 전송되지 않았습니다」

## 5. B — 확인용

`scripts/laws/compare_ab.mjs`(또는 vitest) — 같은 입력에 A 의 매핑 판정과 B(`checkRules`) 를 돌려 status 가 다른 매핑만 출력. 단위 테스트에서 표본 취업규칙으로 「불일치 0 또는 설명된 불일치」를 확인한다.

## 6. C — 선택 정밀검토

- 오프라인 배치 먼저: 공개 표본에 `/취업규칙검토` 를 돌려 변경지시 JSON 을 얻고, A 결과와 조문별로 맞춘 비교 리포트(`docs/work-rules-ac-compare.md`)를 낸다 — 일치·A 만·C 만
- **표본은 공개 자료만** — 고객사 취업규칙 금지(금지선 1, C 는 외부 모델을 쓴다). 표준취업규칙 옛 판 등
- 온라인 C(서버1 엔드포인트·동의 화면)는 **런칭 결정 뒤** 별도 작업으로 한다. 이번 범위는 비교 리포트까지

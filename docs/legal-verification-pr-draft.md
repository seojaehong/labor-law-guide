## 문제와 변경

법조문 캐시 조회 실패·자료 부족이 문제 없음과 구별되지 않았고 채팅은 검증 전에 생성 본문을 전송했습니다. 이제 캐시 참조 확인과 의미·적용성 검토를 구분하며, 오류·미설정·타임아웃·잘못된 응답·근거/시행일 누락·중복 개정을 검토 필요로 처리합니다.

모델 본문은 출력 전에 검사합니다. 모든 명시적 참조가 확인된 완성 응답은 검토 고지를 먼저 표시한 미검수 참고 초안으로 제공하며, 미확인 참조 혼합·범위 인용·불완전 생성·명시적 확신 과장은 보류합니다. 인용부호, 같은 법명 뒤 복수 조문, 미지원 법률·시행령·시행규칙을 처리하고 정상 법명인 근로자퇴직급여 보장법을 보장 주장과 구별합니다. 조회 기준일과 사건 발생일·경과규정·사업장 적용 여부의 미확인을 명시합니다.

취규의 기간·상시 점검을 유지하면서 근거/시행일 누락 및 상충 문구를 검토 필요로 낮춥니다. Python 원본 44개 규칙은 lawId로 index와 연결하고 검토 필요 상태도 CLI/JSON으로 출력합니다. 요청·응답 취소 시 private collector가 중단되고 취소를 공급자 fallback으로 재시도하지 않습니다. 검증 조회에도 취소 신호를 연결했습니다.

## 검증

합성 입력만 사용했습니다. 전체 918개 중 916개 통과했고, 홈 화면 실패 2건은 원본 master에서도 재현했습니다. 게이트·취소·원본 CLI 집중 검사 68건, 변경 파일 lint·타입 검사·Python 구문·매처 parity를 통과했습니다. 전체 lint는 변경하지 않은 파일의 기존 8 errors / 18 warnings로 실패합니다.

동일한 외부 placeholder URL에서는 기준 master와 변경 브랜치 모두 FAQ 정적 생성 60초 시간 초과가 재현됐습니다. 합성 Supabase loopback fixture에서는 두 브랜치 모두 전체 빌드(103개 정적 페이지 포함)가 종료 코드 0으로 완료됐습니다. fixture는 운영 DB 검증을 대체하지 않습니다. 조사·재현 명령·오류 증거는 docs/legal-verification-review.md에 있습니다.
